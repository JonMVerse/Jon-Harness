Metabase MCP — setup guide

Jonathan drives the terminal. Yuval unlocks 1Password and tests it afterwards.

For: Jonathan Aghimien & Yuval Rubin Time needed: ~15 minutes
Goal: Yuval can ask Metabase questions directly inside Claude Desktop. The API key is never written to disk — it is resolved live from 1Password each time the app launches.

Who does what

Jonathan

Runs the script in Terminal, watches the output, handles any path issues.

Yuval

Flips one 1Password setting, approves Touch ID prompts, then tests it.

Before the session — Jonathan (quick prep on Yuval's Mac)

  • Homebrew is installed  command -v brew
  • The 1Password desktop app is installed and Yuval is signed in
  • Yuval has access to the "Product and tech" vault (confirmed ✓)
  • The script file setup-metabase-mcp.sh is copied onto her Mac (e.g. Desktop or Downloads)

Note: uv, the 1Password CLI, and jq do not need to be pre-installed — the script handles it.

In the session — do these in order

1

Turn on the 1Password CLI link

Yuval

This is the one step that cannot be scripted.

  • Open the 1Password desktop app.
  • Go to Settings → Developer.
  • Turn ON "Integrate with 1Password CLI".
  • Quit 1Password completely (Cmd-Q) and reopen it.
  • Leave 1Password unlocked for the next step.
2

Run the script

Jonathan

Open Terminal on Yuval's Mac and run:

bash ~/Desktop/setup-metabase-mcp.sh

Adjust the path to wherever you copied the file. You should see green ticks for:

- op  →  /opt/homebrew/bin/op
- uvx →  /opt/homebrew/bin/uvx
- Read 'op://Product and tech/metabase/api key' — OK
- Wrote 'metabase' server into ... claude_desktop_config.json

Yuval: a Touch ID prompt may appear — approve it.

If you see "Could not read the key from 1Password yet": Step 1 wasn't fully applied. Re-do Step 1 (especially: quit & reopen 1Password, make sure it's unlocked), then run the script again. It's safe to re-run.
3

Restart Claude Desktop

Either
  • Quit Claude Desktop completely (Cmd-Q) — not just closing the window.
  • Reopen it.
4

Test it

Yuval

In a new Claude Desktop chat, try:

"Using Metabase, list my dashboards."

The first Metabase request each session may trigger a Touch ID prompt — that's expected.

Day-to-day — what to tell Yuval

Just open Claude Desktop and ask Metabase questions as normal.
The one thing that must be true: 1Password is open and unlocked. The key is fetched from 1Password at launch — nothing sensitive is stored on the laptop.
If Metabase ever "stops working", it's almost always because 1Password is locked. Unlock it and restart Claude Desktop.

Troubleshooting

"metabase" not appearing in Desktop

Confirm Claude Desktop was fully quit (Cmd-Q) and reopened. Re-run the script and check the printed paths look real.

Key / startup errors

Make sure 1Password is open and unlocked, then restart Claude Desktop.

Intel Mac

Paths resolve to /usr/local/bin automatically — the script handles it. Confirm the printed op → and uvx → lines look correct.

Fallback if 1Password CLI is fiddly on the day

You can hard-code the key inline in ~/Library/Application Support/Claude/claude_desktop_config.json as a stopgap:

"metabase": {
  "command": "/opt/homebrew/bin/uvx",
  "args": ["metabase-mcp"],
  "env": {
    "METABASE_URL": "https://metabase.multiverse.io",
    "METABASE_API_KEY": "<paste key from 1Password>"
  }
}

⚠️ The key sits in plaintext. Use only as a stopgap, then switch back to the 1Password version.

Reference — what the script writes

File: ~/Library/Application Support/Claude/claude_desktop_config.json
The script merges this in and leaves any other settings untouched.

"metabase": { "command": "/opt/homebrew/bin/op", "args": ["run", "--no-masking", "--", "/opt/homebrew/bin/uvx", "metabase-mcp"], "env": { "METABASE_URL": "https://metabase.multiverse.io", "METABASE_API_KEY": "op://Product and tech/metabase/api key" } }
  • Claude Desktop and Claude Code are separate apps that read different config files. This runbook is for Desktop only.
  • There is no hosted Metabase MCP — the community metabase-mcp server runs locally via uvx. That's why local setup is required.
